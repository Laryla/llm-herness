# 领域文档

本文件规定工程 Skills 在浏览和修改代码前如何读取本仓库的领域文档。

## 开始探索前需要读取

- 读取仓库根目录的 `CONTEXT.md`。
- 如果根目录以后出现 `CONTEXT-MAP.md`，由它指向各上下文的 `CONTEXT.md`，只读取与当前任务相关的上下文。
- 读取 `docs/adr/` 中与当前工作区域有关的架构决策。

如果上述文件或目录不存在，直接继续，不需要报告缺失，也不要提前建议创建。`domain-modeling` 会在术语或决策真正确定时按需创建它们。

## 文件结构

本仓库当前采用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
└── server/、web/ 等实现目录
```

只有在系统发展出多个具有独立语言和所有权边界的上下文后，才升级为根目录 `CONTEXT-MAP.md` 加各上下文独立 `CONTEXT.md` 的布局。

## 使用词汇表中的语言

Issue 标题、重构建议、假设、测试名称和代码中的领域概念，必须使用 `CONTEXT.md` 定义的规范术语，不得漂移到词汇表明确要求避免的同义词。

如果需要的概念尚未出现在词汇表中，应先判断它是否只是通用工程术语；只有真实的领域语言缺口才交给 `domain-modeling` 澄清和记录。

## 标记 ADR 冲突

如果计划或实现与现有 ADR 冲突，必须明确指出冲突，不得静默覆盖。例如：

> 与 ADR-0007 冲突——但由于新的约束，值得重新讨论。
